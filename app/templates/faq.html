Frequently asked questions

Getting started

Do I need a developer or automation experience to use this?

No. Upload the documents you already have and follow the on-screen prompts — Req2QA handles the technical work of generating test coverage and, if you want it, running tests against your environment. You never write, read, or maintain a test script yourself.

Should I trust AI-generated test cases?

Think of it as hiring a fast, tireless junior tester — without the weeks it takes to recruit, onboard, and train one. Req2QA doesn't claim to be 100% accurate, and it doesn't remove the need for a human in the loop: every test case should be reviewed before you rely on it. What it does do is the time-consuming first pass to the best possible outcome, then hands it to you to approve, correct, or tick off — and because every test case is mapped back to the requirement it covers in a traceability matrix, you're reviewing targeted, mapped output rather than starting from scratch. Compare that to the actual cost of hiring a junior tester (recruiting, training, ramping up, and paying them to write the same coverage) — the time and money saved getting to "reviewed and approved" is the real value, not a claim of perfection.

Can Req2QA test our custom-built (not off-the-shelf) application?

Yes — Custom Application Mode reads a process-flow diagram and a short brief about your app, then confirms its understanding with you before generating anything.

Compatibility

Does live execution work with every login and every application?

Live execution works best with standard web applications using plain page structure and a standard username/password login. Some modern interfaces — particularly those built with heavily componentized, web-component-based frontends — can limit what our engine is currently able to see and interact with on a given screen. Applications that require hardware-token, smart-card, or biometric multi-factor login are also not currently supported, since there's no standard login step to automate — this is consistent with how other test-automation tools in the market handle these same login types today. As part of onboarding, we'll check your application's platform and login method with you first to confirm it's a good fit before any paid engagement begins.

Pricing

What does this cost?

We publish our actual rate card on our Pricing page — a base allowance plus a per-test-case rate for each tier (generation, execution, or both), so you can see exactly how a number is built. Your specific invoice still depends on how many test cases you generate and/or execute, so tell us what you're testing and we'll work out the exact figure with you.

Privacy & security

Is my data safe?

Yes. Your credentials are used once, in memory, to run a live-execution test, and are never stored or logged. Uploaded documents are used only to generate your report and aren't retained afterward — only the resulting report is kept, and only for 7 days. Analysis is powered by a leading AI model, used solely to generate your report and never to train anyone else's model. See our Security Overview and Privacy Policy for the full detail.

What happens to my uploaded documents?

They're used only to generate your report and are not retained afterward. Only the resulting report and workbook are kept, for up to 7 days, reachable only via your private link — shown to you right after the run completes. Closed the tab before saving it? Look it up again anytime in Run History using your access code.

Considering your options

Why not just build this myself with AI?

You could — the same way you could build your own accounting software instead of buying one. What you're paying for isn't access to an AI model; anyone can get that. You're paying for the logic and sequencing already built and refined through hands-on testing against real-world requirements formats and live web applications — the weeks of trial and error it takes to get an AI agent to reliably read a spec, generate test cases that actually matter, map them to a traceability matrix, and drive a real browser through a live system without tripping over things like multi-step forms or toggle switches. Req2QA exists so you don't have to build and debug that yourself.
